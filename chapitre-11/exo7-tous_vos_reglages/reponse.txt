Le réglage fantôme : depthZeroToOne est seulement déclaré : le champ existe, avec sa valeur de départ, mais aucun backend ni l'application ne le lit. La personne qui le règle croit changer la convention de profondeur, une profondeur de 0 à 1 au lieu de -1 à 1, et s'attend à voir le rendu changer. En réalité, rien ne se passe : la valeur est écrite dans un champ que personne ne consulte, le comportement reste celui du code. Pire, rien ne le signale : le réglage a l'air accepté, et la personne cherche ailleurs la cause d'un effet qui n'existe pas. Il faut soit le brancher sur le code qui en dépend, soit le retirer.

La lecture cachée : openXrLoaderPath est classé CACHE. Un menu peut bien poser le champ, mais le backend ne lit pas ce champ : il appelle lui-même getenv sur NK_XR_OPENXR_LOADER. Le choix du menu est donc court-circuité. Si la variable est définie, c'est elle qui gagne, quoi que dise le menu ; si elle ne l'est pas, le backend ne voit pas non plus la valeur du menu et charge le loader standard. Dans les deux cas, le menu affiche un chemin qui n'est pas celui qui est chargé. Sur un casque autonome, sans terminal pour définir la variable, ce réglage ne peut tout simplement pas être changé. Cela contredit aussi la règle du module : les variables d'environnement ne doivent entrer que par NkXrApplyEnvOverrides, à un seul endroit.

Le menu : Sur les 9 réglages, 5 sont des champs lus et posés quelque part : renderScale, halfRate, submitDepthLayer, listExtensions et displayHz. Une personne casque sur la tête pourrait changer ces 5 depuis un menu. Pour les 4 autres, il faut corriger le code. openXrLoaderPath et shotFrame : retirer les getenv directs, faire lire le champ par le backend, et laisser NkXrApplyEnvOverrides seule poser le champ depuis NK_XR_OPENXR_LOADER ; shotFrame n'est même pas déclaré, il faut d'abord en faire un champ. depthZeroToOne : le faire lire par le code de rendu qui en dépend, ou le supprimer. syncCopyDiagnostic : il est lu mais personne ne le pose, il reste à sa valeur de départ ; il faut permettre de le poser par le code (et donc un menu) et l'ajouter à NkXrApplyEnvOverrides si on veut le régler sans recompiler.
